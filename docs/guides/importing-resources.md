# Importing Existing Resources

Objects that already exist in Infoblox, whether created manually, by scripts, or by another tool, can be brought under Terraform management without recreating them. Every resource in the Infoblox provider supports import on each backend it is available for.

## Import IDs

A resource is imported using its `id`. The format depends on the backend configured in the provider:

| Backend | Import ID | Example |
|---------|-----------|---------|
| NIOS | WAPI object reference (`_ref`) | `record:a/ZG5zLmJpbmRfYSQuX2RlZmF1bHQuY29tLmV4YW1wbGUsc2FtcGxlLDE5Mi4xNjguMS4xMA:example.mydomain.com/default` |
| UDDI | Object resource identifier | `dns/record/2f3e9a1c-7b4d-4e2a-9c61-5d8f0a1b2c3d` |

To find the ID of an existing object, use the NIOS Grid Manager or WAPI for NIOS, or the Infoblox Portal or API for UDDI. You can also use the resource's [list resource](#finding-objects-to-import) to look it up from Terraform.

## Using Import Blocks

Import blocks let you import resources declaratively as part of the normal plan and apply workflow. Add an `import` block with the resource ID and a matching `resource` block:

### NIOS Backend

```terraform
import {
  to = infoblox_record_a.example
  id = "record:aZG5zLmJpbmRfYSQuX2RlZmF1bHQuY29tLmV4YW1wbGUsc2FtcGxlLDE5Mi4xNjguMS4xMA:example.mydomain.com/default"
}

resource "infoblox_record_a" "example" {
  nios = {
    name     = "example.mydomain.com"
    ipv4addr = "192.168.1.10"
  }
}
```

### UDDI Backend

```terraform
import {
  to = infoblox_record_a.example
  id = "dns/record/2f3e9a1c-7b4d-4e2a-9c61-5d8f0a1b2c3d"
}

resource "infoblox_record_a" "example" {
  uddi = {
    name_in_zone = "example"
    zone         = "dns/auth_zone/8a1b2c3d-4e5f-6a7b-8c9d-0e1f2a3b4c5d"
    rdata = {
      address = "192.168.1.10"
    }
  }
}
```

Run `terraform plan` to preview the import, then `terraform apply` to add the resource to the state. After the import, update the configuration as needed so that `terraform plan` shows no changes.

> For **NIOS backend** The plan shows 1 to import and 1 to update. The update attaches the `Terraform Internal ID` extensible attribute to the imported object.

## Generating Configuration

If you do not want to write the `resource` block by hand, Terraform can generate it for you. Add only the `import` block, then run:

```bash
terraform plan -generate-config-out=generated.tf
```

Terraform writes the configuration for each imported resource to `generated.tf`. Review the file, adjust it as needed, and run `terraform apply` to complete the import. For more information, see [Generating Configuration](https://developer.hashicorp.com/terraform/language/import/generating-configuration) in the Terraform documentation.

> Generated configuration is only a starting point and may need manual changes before `terraform apply` succeeds. This also applies to configuration generated by `terraform query`. For more information, see the [limitations of generated configuration](https://developer.hashicorp.com/terraform/language/import/generating-configuration#limitations).

## Using the Import Command

You can also import a single resource with the `terraform import` command. Write the `resource` block first, then run:

```bash
# NIOS backend
terraform import infoblox_record_a.example record:a/ZG5zLmJpbmRfYSQuX2RlZmF1bHQuY29tLmV4YW1wbGUsc2FtcGxlLDE5Mi4xNjguMS4xMA:example.mydomain.com/default

# UDDI backend
terraform import infoblox_record_a.example dns/record/2f3e9a1c-7b4d-4e2a-9c61-5d8f0a1b2c3d
```

Unlike import blocks, this command changes the state immediately and does not show a plan first.

> For **NIOS backend** The first `terraform apply` after the import attaches the `Terraform Internal ID` extensible attribute to the imported object. Plans after that show no changes.

## Finding Objects to Import

Every resource has a matching list resource that searches for existing objects. Use it with `terraform query` to find objects by filters or tags and get their IDs:

```terraform
list "infoblox_record_a" "existing" {
  provider = infoblox
  config {
    filters = {
      comment = "Created manually"
    }
  }
}
```

Running `terraform query -generate-config-out=generated.tf` writes both `import` and `resource` blocks for the objects it finds, which you can then apply. For more information, see [terraform query](https://developer.hashicorp.com/terraform/cli/commands/query) in the Terraform documentation.

## NIOS Backend Notes

* On import, the provider adds the `Terraform Internal ID` extensible attribute to the NIOS object and saves it in the state. If the object already has this attribute, its value is replaced with a newly generated one. For more information, see [Management of Provider Operations with Terraform Internal ID](tf-internal-id-management.md).
* An object should be managed by only one Terraform configuration. Importing the same NIOS object into another configuration replaces its Terraform Internal ID, and the first configuration will no longer be able to track it.
